# 价值等级接入方案（方案 B · 修订版）

> 前提：**颜色＋罗马数字 = 价值的"次序"，不是分数。**
> 所以页面里不出现 1–16、不出现百分比、不出现"第 N 档"。只显示标签本身（如 `金III`），比较时只说"高一档／低一档／同档"。

## 一、数据层

### 1.1 新增 `src/data/chessValue.ts`

```ts
export type TierColor = '钻' | '辉金' | '金' | '紫' | '蓝' | '绿' | '白';

export interface Tier {
  label: string;               // 展示用：'金III' / '钻' / '辉金'
  color: TierColor;            // 配色用
  roman?: 'I' | 'II' | 'III';  // 钻、辉金没有
}

// 顺序表：数组位置只表示"谁高谁低"，不表示分值。
export const VALUE_LADDER: Tier[] = [
  { label: '辉金', color: '辉金' },
  { label: '金III', color: '金', roman: 'III' },
  ...
  { label: '白I', color: '白', roman: 'I' },
];

export function parseTier(label: string): Tier | null;
export function tierColorClass(label: string): string;   // 复用 tierColors，只按底色查
export function compareTier(a: string, b: string): number; // -1 / 0 / 1，只比先后
```

要点：

- `钻` 不进 `VALUE_LADDER`，单独判断（`label === '钻'` 时直接返回钻样式）。
- `VALUE_LADDER` 里不要写 `rank: 1..16` 这种数字字段，避免又变成"分"。排序就按数组下标。

### 1.2 `src/data/fragments.ts` 的 `chessPieceTiers`

**星号不动**：等级字符串原样保留 `*`，不拆字段、不加布尔标记。

```ts
{ letter: 'Q', name: '后', tier: '金III', count: 1 }
{ letter: 'M', name: '老鼠', tier: '辉金*', count: 1 }
```

- `tier` 同时承担三件事：底色、罗马数字、星号，展示时原样输出。
- 解析颜色/排序时才临时 `stripStar()`，不改原字符串。
- 24 条全部替换：钻 / 辉金* / 金III·金II*·金I* / 紫III·紫II*·紫I* / 蓝III·蓝III*·蓝II·蓝I* / 绿III*·绿I* / 白III·白II*·白I*。

### 1.3 `src/sections/chessRulesModel.ts` 的 `poisonData`

```ts
interface PoisonStage { from: number; to?: number; effect: string; tier?: string }
interface PoisonEntry { letter; piece; base?: string; levels: PoisonStage[]; immune?: boolean; note?: string }
```

- `from`/`to` 表示中毒次数区间（如 `−1～−3`），区间内效果与价值相同。
- `tier` 为空 = 该段结束时已被移除，页面显示 `—`。
- 免疫层的 `tier` 填原等级，徽章显示"没掉级"。
- 原本合并的卡（兵/象/骷髅、后/鸵鸟、猫/缅因猫/英语/天线）按每枚棋子的实际价值拆开，避免一张卡里出现两个答案。

## 二、渲染层

### 2.1 棋子等级页（`ChessRules.tsx` 的 `tiers`）

- 卡片按 `compareTier` 降序排，钻排最上。
- 卡面只显示：`金III`、棋子名、×数量、英语禁区标记。**不显示序号、不显示分数。**
- 顶部加一条横向阶梯条（`VALUE_LADDER` 的 16 格 + 钻），有棋子的格高亮——这就是方案 C 的视觉效果，但不新增 tab。

### 2.2 中毒查询页（`poison`）

- 每条效果行右侧加档位徽章，颜色按底色走。
- 免疫层：不显示徽章，写"不变"。
- 被移除：显示 `—`。
- 卡片头写 `金III → 紫II`（只写标签，不写"剩余 %"）。

### 2.3 配色（`chessRulesModel.ts`）

- `tierColors` 保持按底色 key（'金' / '紫' / …）。
- 新增 `tierColorClass(label)`：`parseTier` 拿底色再查表。
- 删掉现在 `piece.tier.replace('*','')` 直接查表的写法——否则 `金III` 查不到会 fallback 成灰色。

## 三、多语言

- 所有新等级标签要进 `MANUAL_EN`：Diamond / Glow Gold / Gold III / Purple II / Blue I …
- 中毒行拆成两个 `<span>`：`effect` 一个、`tier` 一个，各自 `L()`，不要把整行塞进 `L()`。
- `src/data/fragments.en.ts` 的 `chessPieceTiersEn` 同步成英文标签。

## 四、不做的事

- 不做百分比、不做分数、不做"第 N 档"。
- 不新增 tab（现在 5 个：棋子规则 / 棋子等级 / 对弈 / 特殊机制 / 中毒查询，手机端已经换行）。
- 不动棋盘引擎：`poisonData` 只影响展示，实际中毒判定仍走 `rules.ts`；等中毒规则定稿再改引擎。

## 五、验收

- 24 张等级卡按价值降序、钻在最上。
- 中毒卡每层都有徽章；免疫层显示原等级，移除层显示"—"。
- 中文、英文两版都不漏翻。
- `tsc` / `build` 通过。

实现口径（与原始表的差异，均已按"同能力同值"处理）：

- **后 / 鸵鸟共用四段阶梯**：8方向2格 → 8方向1格 → 4方向1格 → 移除。二者是同一枚棋的两种形态，原表只给鸵鸟写了三行，这里补齐第三段。
- **猫 / 缅因猫 / 英语 / 天线**：原表只写到 −4，移除层沿用 −7（旧规则），待定稿后再改。
- **猫娘**：1–4 段均为"失去猫能力"，仍记 `钻`（不带罗马），与"关键棋子不排层级"一致。
