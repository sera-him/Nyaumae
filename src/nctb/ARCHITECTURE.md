# NCTB 题库架构决策（v2）

1. `specs/` 定义测量构念、排除项、题型家族和难度来源；题目不能反向定义构念。
2. `banks/` 只保存可下发题面。正式题不含答案、提示或解释；`scoring/answerKeys.ts` 保存独立答案键，`review/` 保存不会被运行时导入的编辑审查依据。
3. `questionBank.ts` 暴露单一正式题库的 `questionsFor`、`getNctbQuestion`、`EXAM_QUESTIONS` 和 `FORMAL_QUESTIONS` 门面；所有题目都进入标准考试。
4. 选项 ID 是确定性不透明值；显示顺序由会话 seed 决定。这样可复现且不会用 `correct` 暗示答案。
5. `generation/` 与 `scripts/nctb/` 只在开发/构建阶段使用 AI：候选生成与独立复核分开，审核后才人工固化为静态版本。正式作答运行时不调用 LLM。
6. 当前产品是纯静态前端。即使公题和答案键分层，浏览器端本地评分仍会把答案键打入某个客户端 chunk；这只是迁移到服务端评分前的清晰边界，不是防泄漏方案。
7. `formal-a-v1` 是可复现的高质量试点题库，不代表完成心理测量学标定。增加题量前仍需独立 AI 审核、人工专家审查、试测、项目分析和版本冻结。
