## 安全加固（XSS / 供应链纵深防御）
- 用户问 PHP?→澄清技术栈；随后追问"静态站是否不怕黑客"，逐层指出 XSS / 供应链 / 缺 CSP 才是真风险面。
- 落三处改动：① 新建 `public/_headers`（Cloudflare Pages 安全头）：CSP（script-src 'self' 'wasm-unsafe-eval'、style-src 带 'unsafe-inline'、connect-src 放开 https:+http://localhost:* 给 BYOK、worker-src blob:）、HSTS、X-Content-Type-Options、X-Frame-Options DENY、X-XSS-Protection:0、Referrer-Policy、Permissions-Policy、COOP same-origin。② `index.html` 删掉 `<link ... onload="this.media='all'">` 内联事件处理器（会触发 CSP 拦截致字体异常），改普通 stylesheet 链接。③ `src/components/ui/chart.tsx` 的 ChartStyle 给注入 <style> 的 id/key/color 加 `isCssSafe` 字符校验（拦 <>"'\ 与控制字符），纵深兜底。
- 验证：tsc -b 通过（exit 0）；grep 确认全 src 无 eval/new Function（CSP 无需 'unsafe-eval'）；全项目仅 1 处 dangerouslySetInnerHTML（chart.tsx，已加固）；无内联脚本（仅 index.html 外部 module 脚本）。
- 残留项（未自动处理，避免 breaking）：`npm audit --omit=dev` 报 1 low——katex ≤0.18.1 原污染(GHSA-238p-pmpm-9mq7)，fix 需 katex@0.19.0 破坏性升级（react-katex 连带），需先 build+数学页目检再升。建议后续单独处理。
- CSP 设计取舍记录：BYOK 架构下 connect-src 无法限制外发（主防御靠 script-src 阻断脚本）；web-llm 本地推理必须 'wasm-unsafe-eval'；React 内联 style 属性必须 style-src 'unsafe-inline'，故样式注入风险交 CSP+字符校验双重兜底。
- **复盘：CSP 漏掉第三方 iframe（真回归，已修）**。Playground.tsx:294 `scratchUrl` 用 `https://www.haohaodada.com/new/Scratch3/index.html?id=` 跨域嵌入 Scratch 小游戏（:405 `<iframe src={frameSrc}>`）。初版 CSP 没设 frame-src，会回退 default-src 'self' 把 iframe 拦白屏。已在 CSP 加 `frame-src 'self' https://www.haohaodada.com https://haohaodada.com`。**教训：上 CSP 前必须 grep 全 src 的 `<iframe>`/`new Worker`/跨域 `src=` 并逐一放行，不能只测主站资源。**
- 影响面核验（用户问"是否影响体验"）：麦克风/语音(getUserMedia/SpeechRecognition) 全 src 无 → Permissions-Policy 禁用 mic 无碍；WebSocket/ws:// 无 → wss: 冗余无害；`<object>/<embed>` 无 → object-src 'none' 安全；仅 Playground 跨域 iframe 是真坑（已修）。index.html 字体由 async media/onload 改普通 stylesheet 链接，代价仅是 fonts.css 变 render-blocking（unicode-range 子集，实测无感），换取 CSP 兼容。
